## Tool shapes (exact; the code is the source of truth)

### `search_products` (live)

Arguments. All are optional; unknown keys are ignored.

```ts
{
  q?: string;                 // free text, e.g. "quiet wireless keyboard"; stopwords and prices are ignored
  category?: string;          // "mechanical_keyboard" | "headphones"; loose values resolve ("keyboard" → mechanical_keyboard)
  max_price_cents?: number;   // int > 0; filters on list price
  must_have?: string[];       // hard needs, e.g. ["silent","wireless"]; word match with synonyms (quiet~silent, wireless~bluetooth)
  run_id?: string; buyer_id?: string; buyer_model?: string;   // simulated buyers only, used for events
}
```

Response (`structuredContent`; `content[0].text` is a readable summary of the same):

```ts
{
  results: Array<{
    listing: {               // @sa/shared Listing (inventory stripped)
      id: string; seller_id: string; seller_name: string; category: string;
      title: string; description: string;
      specs: Record<string, string | number | boolean>;
      list_price_cents: number; shipping_days: number; in_stock: boolean;
      mcp_url: string;       // = the gateway URL; every tool lives on this one connector
    };
    fit_note: string;        // "Matches: quiet, keyboard." or "Does not meet: usb hub."
  }>;                        // at most 5, best fit first
  relaxed: boolean;          // true = nothing met every need; these are the closest options
  note?: string;             // e.g. "Unknown category …; available: …"
}
```

For E2's `McpGateway`: read `structuredContent.results[i].listing`. Sending `query` is harmless, but only `q` is used.

Each response is E1's `ExchangeResponse` plus `buyer_id`. `buyer_id` is resolved in this order: the caller's `buyer_id`; else `oai_` + sha256(ChatGPT `_meta["openai/subject"]`), which is stable per person, needs no echo, and never stores the raw subject; else a minted `anon_<uuid>` that the model must send back (missing or wrong → `wrong_buyer`). `buyer_id` is optional on later calls when the subject is present.

## Verified: no double charge (main `ca7f6a3`)

- The only charge site is `payDeal` in `@sa/payments` (`paymentIntents.create`). It's called only from S2's `pay_deal` handler. The exchange (`accept_deal`) never imports `@sa/payments`.
- Runtime check with the real `Exchange` and a counting `payDeal`:
  - offer and accept ×2: **0 charges**
  - `pay_deal` by another buyer: `refused`, 0 charges
  - `pay_deal` ×2 with different cards: **1 charge**, exactly the stored total ($129); the second returns `already_paid`
  - the negotiation ends `paid`

## Decided with Vivan (10:16 pm): buyer identity

The exchange binds offers to `ctx.buyer_id`, but ChatGPT and Claude send none, and the gateway is stateless.

- **Gateway (Esha):**
  - If a negotiation call has no `buyer_id`, the gateway mints `anon_<128-bit random>` and passes it as `ctx.buyer_id`.
  - The tool response returns `buyer_id`, and the model sends it back on `make_offer`, `accept_deal`, `check_offers` and `walk_away`.
  - Simulated buyers keep their own `buyer_id`; the gateway never overrides one.
- **Exchange (Vivan):**
  - **Binding needs no change.** The random id keeps `wrong_buyer` (exchange.ts:253) effective.
  - **Restart probing:** a new chat gets a new `anon_` id. That resets `StartLimiter`, buyer memory (`memoryKey(buyer_id, product_id)`, exchange.ts:134/139) and `buyerEndpoint` (probing.ts:26).
  - **Suggested fix:** for `anon_` ids, also key the start limit and best-offer memory by product across all anonymous buyers, so a fresh id never beats the last anonymous offer.
  - **Optional:** echo `ctx.buyer_id` in `ExchangeResponse`.
