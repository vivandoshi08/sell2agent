## Tool shapes (exact; the code is the source of truth)

### `search_products` (live, contract v2; PR #54)

Arguments (all optional; unknown keys ignored):

```ts
{
  query?: string;             // e.g. "quiet wireless keyboard"  (alias: q)
  category?: string;          // "mechanical_keyboard" | "headphones"; loose values resolve ("keyboard")
  max_price_cents?: number;
  hard_needs?: string[];      // e.g. ["silent","wireless"]; synonyms (quiet~silent)  (alias: must_have)
  preferences?: { price?, quality?, delivery?, warranty?, trust?, convenience? };  // weights 0..1 (LeverProfile)
  run_id?: string; buyer_id?: string; buyer_model?: string;
}
```

Response (`structuredContent`):

```ts
{
  listings: Listing[];        // contract SearchProductsOutput: ≤5, best fit first
  results: Array<{ listing: Listing; fit_note: string; fit_score?: number /* 0..1, with preferences */;
                   levers_offered: { id; lever; label }[] /* public, never costs */ }>;
  relaxed: boolean;           // nothing met every need; closest options
  note?: string;
}
```

Ranking: hard needs filter first. With `preferences`, the weighted fit decides the order (price, quality, delivery, warranty, convenience; trust is neutral until there's seller data). Without them, query matches and then price. On production: `{quality:1,warranty:0.8}` → TypeWell > KeyForge > ClackCo; `{price:1}` → ClackCo first; `{delivery:1}` → TypeWell first.

Each response is E1's `ExchangeResponse` plus `buyer_id`. `buyer_id` is resolved in this order: the caller's `buyer_id`; else `oai_` + sha256(ChatGPT `_meta["openai/subject"]`), which is stable per person, needs no echo, and never stores the raw subject; else, on a first `make_offer` only, a minted `anon_<uuid>` that the model must send back. A later call with no `buyer_id` and no subject gets `missing_buyer_id` ("send the buyer_id from your first make_offer response"); a wrong id gets `wrong_buyer`. The subject is hashed with an HMAC keyed by `EXCHANGE_HMAC_SECRET`.

## Decided with Vivan (10:16 pm): buyer identity

The exchange binds offers to `ctx.buyer_id`, but ChatGPT and Claude send none, and the gateway is stateless.

- **Gateway (Esha):**
  - If a negotiation call has no `buyer_id`, the gateway mints `anon_<128-bit random>` and passes it as `ctx.buyer_id`.
  - The tool response returns `buyer_id`, and the model sends it back on `make_offer`, `accept_deal`, `check_offers` and `walk_away`.
  - Simulated buyers keep their own `buyer_id`; the gateway never overrides one.
- **Exchange (Vivan):**
  - **Binding needs no change.** The random id keeps `wrong_buyer` (exchange.ts:253) effective.
  - **Restart probing:** a new chat gets a new `anon_` id. That resets `StartLimiter`, buyer memory (`memoryKey(buyer_id, product_id)`, exchange.ts:134/139) and `buyerEndpoint` (probing.ts:26).
  - **Suggested fix:** for `anon_` ids, also key the start limit and best-offer memory by product across all anonymous buyers, so a fresh id never beats the last anonymous offer.
  - **Optional:** echo `ctx.buyer_id` in `ExchangeResponse`.
