## Built: the seller decision module

Code picks the price, and the LLM only words it. Import everything from `@sa/seller-mcp/sellers`. Money is integer cents everywhere.

```ts
import { decide, voice, answerQuestion, defaultLlm } from "@sa/seller-mcp/sellers";

// 1. Code decides: action, price, final flag, TRUE reason. Pure, no LLM, ~0 ms.
const move = decide(state, { name: "negotiating" }, buyerProfile?);
//    state: { round, terms: { product_id, title, list_price_cents, floor_price_cents, unit_cost_cents, max_rounds },
//             history: [{ by: "buyer"|"seller", round, price_cents }], buyer_offer_cents? }
//    move:  { action: "offer"|"accept", price_cents, final, reason, reason_text, conceded_fraction }

// 2. (E1 guardrails check `move` here)

// 3. LLM words it. Checked, retried once, then falls back to a safe template.
const { message, source, violations } = await voice(move,
  { terms, prior_prices_cents, buyer_message?, buyer_profile? }, defaultLlm());

// 4. ask_question: grounded in catalog data, or an honest "I don't know" (grounded: false).
const { answer, grounded, fields } = await answerQuestion(publicProduct, question, defaultLlm());
```

| Policy | Behavior | Source |
| --- | --- | --- |
| `static` | List price, fixed, always `final`. The baseline. |  |
| `negotiating` (default) | Holds list in round 1, concedes on t⁴, never more than 75% of the list-to-floor gap | E10 "profit" tactic (+$913 per session vs Boulware in E10) |
| `balanced` | Boulware t³ down to the soft floor by the last round | E5 / E10 |

**Guarantees `decide()` makes in code:**

- Never offers below the soft floor (hard floor + 3% of the gap), and never accepts below the hard floor.
- Never raises a price it already offered.
- Never charges above list, even if the buyer bids more.
- Calls an offer `final` only on the last round.
- `reason_text` never mentions floor or cost.

**`voice()` check:** every dollar figure in the message must be the move price, the list price, or a price already on the table. It must state the move price, not mention floor, cost or margin, and not call a non-final offer final. The buyer's text is wrapped as untrusted. `defaultLlm()` is Claude when `ANTHROPIC_API_KEY` is set (model `SELLER_VOICE_MODEL`, default `claude-sonnet-5-5`), else `null`, which means templates.

**Files:** `types.ts`, `decide.ts`, `voice.ts`, `answers.ts`, `llm.ts`, `index.ts`, `README.md`. Tests are in `apps/seller-mcp/test/sellers.test.ts` (`pnpm test:sellers`).

## Built: the buyer harness

AI buyers shop through a `Gateway` the way ChatGPT would: search, ask, haggle, then buy or walk. Their budget is enforced in code. Import from `@sa/buyer-harness`.

```ts
import { runAll, makeBuyers, LocalGateway, McpGateway } from "@sa/buyer-harness";

const buyers = makeBuyers({ n: 50, models: ["claude", "gpt"], seed: 1, adversarial_share: 0.1 });
const gateway = process.env.GATEWAY_URL ? new McpGateway(process.env.GATEWAY_URL) : new LocalGateway("negotiating");
const { summary, outcomes } = await runAll({ run_id, label: "negotiating", buyers, gateway, concurrency: 4 });
// summary: conversion_rate, safe_conversion_rate, profit_per_buyer_cents, avg_margin_pct, below_floor_deals,
//          wallet_blocks, median_ms_to_first_offer, tokens, by_persona, by_model
```

| Piece | What it is | File |
| --- | --- | --- |
| Personas | price-first, quality-first, speed-first, trust-first, balanced (lever profiles). Each has a stated budget and a higher private walk-away ($95 to $150). | `src/agents/personas.ts` |
| Red-team buyers | about 10%: injected `SYSTEM:` line, fake competitor quote, floor probing | `src/agents/personas.ts` |
| Brains | `ClaudeBrain` (`BUYER_CLAUDE_MODEL`), `OpenAIBrain` (`BUYER_GPT_MODEL`, default `gpt-5`, unverified), `ScriptedBrain` (no LLM, for tests) | `src/agents/brains.ts` |
| Runner + wallet guard | Executes tool calls, blocks any offer or accept above the walk-away, emits events | `src/agents/buyer.ts` |
| `LocalGateway` | In-process stand-in store: 3 keyboard sellers running E2's `decide()` + `voice()` | `src/gateway/local.ts` |
| `McpGateway` | The deployed gateway over MCP Streamable HTTP, 15 s per call | `src/gateway/mcp.ts` |
| `runAll()` + summary | Batch runner and KPIs | `src/run-all.ts` |

**Tools the buyer LLM sees** (dollars; the runner converts to cents): `search_products`, `get_listing`, `ask_question`, `make_offer`, `accept_deal`, `walk_away`. Through `--gateway <url>`, `McpGateway` also sends the run's `strategy` on `make_offer` (honoured only for signed eval run ids) and accepts by `offer_id`.

**Run it:**

```bash
pnpm buyers --compare --n 20 --models claude,gpt     # same buyers: static seller, then negotiating
pnpm buyers --n 20 --models scripted                 # no keys needed
pnpm buyers --policy negotiating --gateway https://<deployed>/mcp
pnpm e2:gate                                         # step-1 gate, 10 scripted buyers × 3 policies
```

**Outputs:** `apps/buyer-harness/runs/` holds a summary, per-buyer outcomes and `<run_id>.events.jsonl`. When `SUPABASE_URL` is set, every event also goes to the `events` table through `logEvent()`. A gateway outage shows as `ERROR gateway: …`, never as a walk-away.

| Run | Policy | Bought | Profit per buyer | Margin | Below floor |
| --- | --- | --- | --- | --- | --- |
| E2 gate, 10 scripted buyers | static | 20% | $14.30 | 53% | 0 |
| E2 gate, 10 scripted buyers | negotiating | 70% | $42.30 | 50% | 0 |
| E2 gate, 10 scripted buyers | balanced | 90% | $50.66 | 48% | 0 |
| Harness, 20 scripted buyers, local gateway | static | 80% | $48.00 | 52% | 0 |
| Harness, 20 scripted buyers, local gateway | negotiating | 95% | $52.85 | 50% | 0 |

**Gate (step 1):** stated price matches code on 135 of 135 messages, 0 ungrounded answers (3 honest "I don't know"), negotiating profit ≥ static, 0 deals below floor.

**Lever gate (step 3, `pnpm e2:lever-gate`): FAILED.** 30 lever-profile buyers with hard dollar limits. `negotiating` earned $48.57 per buyer (83% bought), `lever_policy` $46.87 (80%), `static` $11.53 (17%). Keyboard extras cost the seller $6–8, but the curve cuts only $1–4 a round, so the swap rarely fires. When it did fire, for speed-first buyers, the extra's cost raised the floor and one hard-limit buyer walked. Not tuned to pass. `negotiating` stays the default.

**Bandit (step 3b, `pnpm e2:bandit`): passes vs the current default.** It trained on 1,200 sessions and was tested on 900 held-out buyers. Profit per buyer: learned $49.24, always-`balanced` $50.40, `negotiating` $43.58, `lever_policy` $42.89, `static` $12.58. Learned minus negotiating = +$5.66, 95% CI \[$4.62, $6.70\], 0 deals below floor. But always-`balanced` beats the bandit by $1.16: it under-explored `balanced` for trust-first buyers (n = 7).

**Through E1's real exchange (PR #29, 30 scripted buyers):** static $44.00 per buyer (73% bought), negotiating $44.47 (90%), balanced $45.80 (93%). 0 deals below floor. The exchange's guardrails fired 16 times (injection, probe breaker, concession cap). `balanced` leads again.

**Caveats:**

- `balanced` beat our `negotiating` default in the E2 gate. That's the opposite of E10. Our scripted buyers walk away, and E10's mostly didn't, so the 75% concession cap lost two buyers. Worth a look before the default is final.
- The static seller's numbers depend on the buyer spread. Most gate buyers can't afford list by design.
- The 20-buyer harness run used `ScriptedBrain`, which always picks the cheapest listing. It tests plumbing, not buyer intelligence.
