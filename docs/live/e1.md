- **PR #90 security finding (fix before turning Inkbox on):** a stranger can accept someone else's live offer by email and get its approve link. The Inkbox signature proves Inkbox delivered the webhook, not who wrote the email (no SPF/DKIM result in `message.received`). The door routes by any `off_…` in the text and acts as that offer's buyer; `from_matches_consent` is only logged. Offer ids are in `events.payload.offer_id` for every counter, and `events` is anon-readable. **Reproduced** in a scratch test on main + #90: victim negotiates over MCP (no walk-away, no consent); attacker reads the offer id from events, sends a signed email from their own address with `ACCEPT off_…` → `agreed`, approve link signed for the victim mailed to the attacker. Seller still ≥ floor. **Not exploitable on production today** (no `INKBOX_SIGNING_KEY`; plain JSON needs `OUTREACH_SECRET`). **Fix:** Inkbox mail routes only to a negotiation with follow-up consent whose `followup.reply_to` equals `normalizeAddress(from)`, else unrouted; add the test. Residual: a forged From of the victim's own address can still lock the deal, but the link goes to the victim and nothing is charged.
- **Other #90 checks:** `verifyInkboxSignature` matches Inkbox's spec (request-id/timestamp/signature headers, unix seconds, HMAC-SHA256 over `{request_id}.{timestamp}.{raw}`, `sha256=` hex, 300 s window), constant time. Replays in the window deduped by signed event id. Secret routes fail closed. Nits: `GET /outbox` takes `?key=` (logs; header only); unrouted auto-reply has no global cap.
- **Env on Manufact for #90:** `OUTREACH_SECRET` (required), `FOLLOWUP_DELAY_MS=60000` (demo), `OUTREACH_TICK_MS=15000` or a cron on `/cron/outreach` (Dockerfile sets `NODE_ENV=production`, so the timer is off by default). Leave `INKBOX_*` unset until the fix.

## Interfaces E1 provides

```ts
import { Exchange } from "@sa/seller-mcp/exchange";
const ex = await Exchange.fromEnv();   // Supabase store if SUPABASE_URL is set, else memory (PR #15, on `main`)

// S1 gateway: one call per buyer move
await ex.handle({ kind: "offer",  ctx, product_id, negotiation_id?, offer_price_cents, quantity?, message?, levers?, buyer_profile? }); // make_offer
await ex.handle({ kind: "accept", ctx, negotiation_id, offer_id });   // accept_deal: locks a deal, does NOT charge
await ex.handle({ kind: "walk",   ctx, negotiation_id, reason? });
await ex.handle({ kind: "status", ctx, negotiation_id });             // check_offers
// ctx = { run_id, buyer_id, buyer_model }; buyer_id must be stable per session (offers are bound to it)
// → { ok, negotiation_id, state, status, standing_offer: { offer_id, price_cents, final, expires_at, levers },
//     round, rounds_left, allowed_actions, message, deal?, error?: { code, message } }
// error codes: bad_request, unknown_product, unknown_negotiation, wrong_buyer, not_allowed, stale_offer,
//   unknown_offer, offer_expired, round_cap, rate_limited, bad_lever, closed

// S2 deal card + pay handler
await ex.deals.getLockedDeal(deal_id): Promise<LockedDeal | null>      // read-only; null if unknown or signature fails
await ex.deals.validateForPayment(deal_id, buyer_id, amount_cents?): Promise<PaymentCheck>
//   { ok: true, deal } | { ok: false, code, reason, fix?, payment_intent_id? }
//   code: unknown_deal | tampered | expired | already_paid | wrong_buyer | amount_mismatch | policy_recheck_failed
await ex.markPaid(deal_id, payment_intent_id)   // after payDeal() succeeds; idempotent for the same intent id; negotiation → paid
// LockedDeal: deal_id, negotiation_id, offer_id, buyer_id, seller_id, product_id, title, quantity, unit_price_cents,
//   total_cents, currency, list_price_cents, levers, expires_at (30 min), status: locked|paid|expired, payment_intent_id?, signature
```
